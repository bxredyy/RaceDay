# Commit notes

Add related files together and use a short message that says what changed. For example, `Add event models`, `Add login` or `Fix test cleanup`.

Before each commit, read the changes with `git diff` or `git diff --cached`. Run the relevant tests after changing code.

The brief asks for at least 20 meaningful commits per part. Adding the existing files in groups records when they were added to this repository. It does not show that each feature was developed at that time. Keep the actual dates and make further commits when there is real work to record.

The repository was created after the API was built and tested locally. Earlier Part 1 planning dates cannot be proved by this new repository's history.
